\section{Problema de atribuição gargalo}

O problema de atribuição gargalo, também conhecido como \textbf{Problema de Emparelhamento Min-Max} ou \textbf{Bottleneck Assignment
problem}, é uma variação do problema de atribuição tradicional. O objetivo deste problema é encontrar, em um grafo bipartido ponderado, um emparelhamento de cardinalidade máxima (maior número possível de arestas) no qual o mínimo dos pesos das arestas do emparelhamento seja maximizado \cite{lawler}.

Por exemplo. Considere $N$ trabalhadores e $N$ estações de trabalho. $w_{ij}$ representa a eficiência do trabalhador i na estação de trabalho j. A eficiência total da produção é limitada pela eficiência do trabalhador menos eficiente.  O objetivo é atribuir trabalhadores às estações de trabalho de forma a maximizar a eficiência mínima entre todas as atribuições. \cite{lawler}.

\subsection{Soluções exatas}

A seguir serão apresentadas alguns dos principais métodos para encontrar uma solução exata para o problema de atribuição gargalo.

\subsubsection{Métodos de threshold}

Métodos de threshold funcionam alternando entre duas fases. A primeira fase consiste em selecionar um valor limite, chamado de \textbf{threshold}, descrito por $c\ast$. Na segunda fase, constrói-se um grafo bipartido com todas as arestas cujo peso é menor ou igual a $c\ast$. Em seguida, verifica-se se existe um emparelhamento perfeito nesse grafo. O menor valor de $c\ast$ que permite um emparelhamento perfeito é a solução ótima para o problema de atribuição gargalo \cite{burkard}.

Para selecionar o valor limite $c\ast$, podemos utilizar uma busca binária entre o menor e o maior peso das arestas do grafo original. A cada iteração, ajustamos o valor de $c\ast$ com base na existência ou não de um emparelhamento perfeito no grafo construído. Esse processo continua até que o valor ótimo seja encontrado. \citeonline{burkard}, que descreve esse método, utiliza um algoritmo baseado em matrizes para decidir se um emparelhamento é perfeito ou não, porém podemos utilizar qualquer algoritmo clássico de emparelhamento em grafos bipartidos, como os definidos na seção \ref{sec:algos_exatos_emp_card_max}, como por exemplo o algoritmo de Hopcroft-Karp. Também segundo o autor, o algoritmo tem uma complexidade de tempo de $O(V^{2.5} / \sqrt{\log V})$.

\citeonline{lawler} menciona um método de threshold para solução do problema de atribuição gargalo, porém a definição de threshold dele é levemente diferente, referindo-se ao valor dinâmico do rótulo de um vértice durante busca de caminhos. O algoritmo que ele descreve se assemelha mais aos algoritmos de caminhos aumentantes, que serão discutidos na seção \ref{sec:caminhos_aumentantes_min_max}.

\begin{algorithm}[H]
    \DontPrintSemicolon
    \SetAlgoLined

    % Main Algorithm Body
    \KwLet $C = (c_{ij})$ a matriz de custos $n \times n$ dada;\label{thr:let}\;
    $c_0^* := \min_{ij}\{c_{ij}\}, c_1^* := \max_{ij}\{c_{ij}\}$\label{thr:init}\;
    
    \eIf{$c_0^* = c_1^*$\label{thr:eq}}{
        $z := c_0^*$ \AlgComment{qualquer permutação de $\{1, 2, \dots, n\}$ é ótima}\label{thr:trivial}
    }{
        \While{$C^* = \{c_{ij} : c_0^* < c_{ij} < c_1^*\} \neq \emptyset$\label{thr:loop}}{
            \AlgComment{encontra a mediana $c^*$ de $C^*$;}
            
            % The complex median formula
            $c^* := \min \{ c \in C^* : |\{ c_{ij} \in C^* : c_{ij} \le c \}| \ge |C^*|/2 \}$;\label{thr:median}\;
            
            Testa\_viabilidade($c^*, c_0^*, c_1^*$)\label{thr:check}\;
        }
        
        \If{Testa\_viabilidade ainda não foi executado para $c_0^*$\label{thr:c0}}{
             Testa\_viabilidade($c_0^*, c_0^*, c_1^*$)\;
        }
        
        encontre um emparelhamento perfeito no grafo bipartido atual $G[c_1^*]$\label{thr:final}\;
        $z := c_1^*$ \AlgComment{valor do emparelhamento ótimo}\label{thr:z}
    }
    
    \bigskip % Add some vertical space between the main block and the procedure
    
    % The Procedure Definition
    \Fn{Testa\_viabilidade($c^*, c_0^*, c_1^*$)}{
        construa o grafo atual $G[c^*]$\label{thr:graph}\;
        \eIf{$G[c^*]$ contém um emparelhamento perfeito\label{thr:test}}{
            $c_1^* := c^*$\label{thr:up}\;
        }{
            $c_0^* := c^*$\label{thr:low}\;
        }
    }
    
    \caption{Algoritmo Threshold para o LBAP \cite{burkard}}
    \label{alg:threshold}
\end{algorithm}

O pseudocódigo segue a formulação de \citeonline{burkard}, que minimiza o maior custo $c_{ij}$ da atribuição, e é explicado a seguir com referência às linhas do Algoritmo~\ref{alg:threshold}. Nele, $G[c]$ denota o grafo bipartido que contém apenas as arestas $\{i,j\}$ com $c_{ij} \le c$:

\begin{itemize}
    \item \textbf{Inicialização (linhas~\ref{thr:let}--\ref{thr:trivial}):} O ótimo está sempre entre o menor e o maior custo da matriz, que formam o intervalo inicial de busca $[c_0^*, c_1^*]$ (linha~\ref{thr:init}). O algoritmo mantém a invariante de que $G[c_1^*]$ contém um emparelhamento perfeito, o que vale de início porque $G[\max c_{ij}]$ é o grafo bipartido completo. Se os dois extremos coincidem (linha~\ref{thr:eq}), todos os custos são iguais e qualquer permutação é ótima (linha~\ref{thr:trivial}).
    \item \textbf{Busca binária (linhas~\ref{thr:loop}--\ref{thr:check}):} Enquanto existirem custos estritamente entre os dois extremos (conjunto $C^*$ da linha~\ref{thr:loop}), escolhe-se a mediana $c^*$ desses custos como novo limiar (linha~\ref{thr:median}) e testa-se esse limiar (linha~\ref{thr:check}). Usar a mediana, em vez da média dos extremos, garante que cada teste descarte pelo menos metade dos valores candidatos, independentemente de como os custos estão distribuídos.
    \item \textbf{Teste de viabilidade (linhas~\ref{thr:graph}--\ref{thr:low}):} O procedimento Testa\_viabilidade constrói $G[c^*]$ (linha~\ref{thr:graph}) e verifica se ele tem um emparelhamento perfeito (linha~\ref{thr:test}), o que pode ser feito com qualquer algoritmo de cardinalidade máxima, como o de Hopcroft-Karp. Se tem, o ótimo é no máximo $c^*$, e o extremo superior desce para $c^*$ (linha~\ref{thr:up}); caso contrário, o ótimo é maior que $c^*$, e o extremo inferior sobe para $c^*$ (linha~\ref{thr:low}).
    \item \textbf{Finalização (linhas~\ref{thr:c0}--\ref{thr:z}):} Quando $C^*$ fica vazio, o ótimo é $c_0^*$ ou $c_1^*$. Como $c_0^*$ pode nunca ter sido testado (é o mínimo inicial da matriz), ele é testado nesse momento, se necessário (linha~\ref{thr:c0}); se for viável, o teste rebaixa $c_1^*$ para ele. Por fim, extrai-se um emparelhamento perfeito de $G[c_1^*]$ (linha~\ref{thr:final}), cujo valor ótimo é $z = c_1^*$ (linha~\ref{thr:z}).
    \item \textbf{Complexidade:} Há no máximo $n^2$ custos distintos e cada teste descarta metade dos candidatos, de modo que o laço executa $O(\log n^2) = O(\log n)$ vezes. Cada iteração encontra a mediana em tempo linear no tamanho de $C^*$, $O(n^2)$, e faz um teste de emparelhamento perfeito, que custa $O(E\sqrt{V}) = O(n^{2.5})$ com Hopcroft-Karp, já que $G[c^*]$ tem $2n$ vértices e até $n^2$ arestas. O total é $O(n^{2.5} \log n)$; o limite de $O(n^{2.5}/\sqrt{\log n})$ citado por \citeonline{burkard} exige técnicas mais elaboradas para o teste de emparelhamento.
\end{itemize}

\subsubsection{Método dual}

Assim como os métodos de threshold, o método dual também define um valor limite $c\ast$. No entanto, ao invés de 'chutar' um valor usando busca binária, este método define o valor inicial de $c\ast$ como sendo o menor valor possível que ele pode assumir. Olhando para a matriz de custos, esse valor é o máximo entre os mínimos de cada linha e cada coluna da matriz:

\begin{equation}
    c\ast = \max \left\{ \max_{i} (\min_{j} c_{ik}), \max_{j} (\min_{i} c_{kj}) \right\}
\end{equation}

Com o limite definido, verificamos se é possível encontrar um emparelhamento perfeito no grafo bipartido formado pelas arestas cujo peso é menor ou igual a $c\ast$, usando os mesmos algoritmos de antes. Se um emparelhamento perfeito for encontrado, então $c\ast$ é a solução ótima. Caso contrário, é necessário aumentar o valor de $c\ast$, e para isso nos baseamos no teorema de Kőnig, definido na seção \ref{p:teorema_konig}. 

Sabemos que todas as arestas $c_{ij} > c\ast$ estão conectadas a um conjunto de linhas $I$ e um conjunto de colunas $J$. Essas linhas e colunas ``cobrem'' todas as arestas do grafo atual. Para aumentar o valor de $c\ast$, precisamos adicionar uma nova aresta que não esteja coberta por esses conjuntos. Procuramos o menor peso entre as arestas não cobertas, ou seja, aquelas que não pertencem às linhas em $I$ nem às colunas em $J$. Esse valor se torna o novo $c\ast$:

\begin{equation}
    Novo\space c\ast = \min_{i \notin I, j \notin J} c_{ij}
\end{equation}

A partir daqui, o processo se repete. Com o novo valor de $c\ast$ e a nova aresta adicionada ao grafo, verificamos novamente a existência de um emparelhamento perfeito. Esse ciclo continua até que um emparelhamento perfeito seja encontrado, momento em que o valor atual de $c\ast$ será a solução ótima para o problema de atribuição gargalo.

\begin{algorithm}[H]
    \DontPrintSemicolon
    \SetAlgoLined

    % Line 1
    \KwLet $C = (c_{ij})$ a matriz de custos $n \times n$ dada;\label{dlb:let}\;
    
    % Line 2: Complex Max/Min assignment
    $c^* := \max_{k=1,2,\dots,n} (\min_{i=1,2,\dots,n} c_{ik}, \ \min_{j=1,2,\dots,n} c_{kj})$\label{dlb:bound}\;
    
    % Line 3
    $M := \emptyset$\label{dlb:empty}\;

    % Line 4: While Loop
    \While{$|M| < n$\label{dlb:loop}}{
        construa o grafo bipartido $G[c^*]$\label{dlb:graph}\;
        encontre um emparelhamento máximo $M$ em $G[c^*]$\label{dlb:match}\;
        
        % Line 7: If statement
        \If{$|M| < n$\label{dlb:notperf}}{
            % Line 8
            \KwLet $I \subseteq U$ e $J \subseteq V$ os conjuntos de vértices de uma cobertura mínima de $G[c^*]$\label{dlb:cover}\;
            
            % Line 9: Min assignment with 'not in' notation
            $c^* := \min_{i \notin I, \ j \notin J} c_{ij}$\label{dlb:raise}\;
        }
    }
    
    \caption{Dual\_LBAP: algoritmo dual para o LBAP \cite{burkard}}
    \label{alg:dual_lbap}
\end{algorithm}

Com referência às linhas do Algoritmo~\ref{alg:dual_lbap}:

\begin{itemize}
    \item \textbf{Limite inferior (linhas~\ref{dlb:let}--\ref{dlb:empty}):} Toda linha $i$ precisa ser atribuída a alguma coluna, então o ótimo é pelo menos o menor custo dessa linha; o mesmo vale para cada coluna. O maior desses mínimos é, portanto, um limite inferior para o ótimo e é o valor inicial de $c^*$ (linha~\ref{dlb:bound}). O emparelhamento começa vazio (linha~\ref{dlb:empty}).
    \item \textbf{Teste do limiar (linhas~\ref{dlb:loop}--\ref{dlb:match}):} Enquanto o emparelhamento não for perfeito (linha~\ref{dlb:loop}), constrói-se o grafo $G[c^*]$ com as arestas de custo até $c^*$ (linha~\ref{dlb:graph}) e calcula-se nele um emparelhamento máximo (linha~\ref{dlb:match}). Se esse emparelhamento tiver $n$ arestas, o laço termina e $c^*$ é o valor ótimo, porque nenhum valor menor que o atual foi viável.
    \item \textbf{Aumento do limiar (linhas~\ref{dlb:notperf}--\ref{dlb:raise}):} Se o emparelhamento não é perfeito (linha~\ref{dlb:notperf}), toma-se uma cobertura mínima de vértices de $G[c^*]$, formada pelas linhas $I$ e colunas $J$ (linha~\ref{dlb:cover}); pelo teorema de Kőnig, ela tem exatamente $|M| < n$ vértices. Só uma aresta fora da cobertura, isto é, com $i \notin I$ e $j \notin J$, pode aumentar o emparelhamento máximo, então o novo limiar é o menor custo entre essas arestas (linha~\ref{dlb:raise}). Como nenhum valor intermediário pode tornar o emparelhamento perfeito, o limiar nunca ultrapassa o ótimo.
    \item \textbf{Complexidade:} O limiar cresce estritamente a cada iteração e só assume valores da matriz, de modo que há no máximo $n^2$ iterações; cada uma calcula um emparelhamento máximo e uma cobertura mínima de vértices em um grafo com $2n$ vértices e até $n^2$ arestas. Reaproveitando o emparelhamento da iteração anterior, que continua válido em $G[c^*]$ após o aumento do limiar, cada iteração precisa apenas de uma busca alternante a partir dos vértices livres, em $O(n^2)$, que encontra um caminho aumentante ou, se não houver, a cobertura mínima. Isso dá um limite simples de $O(n^4)$ para o método.
\end{itemize}

O método dual não foi implementado no ambiente de testes deste trabalho. Para o problema de atribuição gargalo, foram comparados o algoritmo Threshold (Algoritmo~\ref{alg:threshold}) e o método de caminhos aumentantes (Algoritmo~\ref{alg:augmenting_lbap}), descrito a seguir.

\subsubsection{Método de caminhos aumentantes}
\label{sec:caminhos_aumentantes_min_max}

Ao contrário do método dual, que ajusta um limiar global para todo o grafo, o método de caminhos aumentantes é construtivo. Ele inicia com um emparelhamento vazio e busca aumentar sua cardinalidade iterativamente, adicionando um par de vértices de cada vez. O objetivo central em cada passo é encontrar um caminho aumentante $P$ que conecte uma linha livre a uma coluna livre, de tal forma que a capacidade desse caminho seja mínima. A capacidade aqui é definida pelo peso da aresta mais cara contida no caminho:

\begin{equation}     
    cap(P) = \max_{\{i,j\} \in P} c_{ij} 
\end{equation}

Para encontrar tal caminho, utiliza-se uma adaptação do algoritmo de Dijkstra. Em vez de somar os pesos das arestas, mantemos para cada vértice um valor de rótulo que representa o ``gargalo'' mínimo necessário para alcançá-lo. Durante a busca, ao tentar estender o caminho de um nó $u$ (com rótulo $d_u$) para um vizinho $v$ através da aresta $\{u,v\}$, o custo não é somado, mas sim comparado. O novo custo potencial para atingir $v$ é o máximo entre o gargalo já existente até $u$ e o peso da nova aresta:

\begin{equation}     
    Novo\space Custo_v = \max(d_u, c_{uv}) 
\end{equation}

O algoritmo seleciona, a cada passo, o nó não visitado com o menor rótulo atual, garantindo uma exploração gulosa que minimiza o gargalo. Assim que uma coluna livre é alcançada por essa busca, o caminho aumentante é identificado e o emparelhamento é expandido, invertendo-se as arestas ao longo do caminho. Esse processo se repete (reiniciando as distâncias) até que um emparelhamento perfeito seja obtido. A solução do problema será determinada pela maior capacidade encontrada entre todos os caminhos aumentantes utilizados na construção.

\begin{algorithm}[H]
    \DontPrintSemicolon
    \SetAlgoLined

    \KwLet $G = (U, V; E)$ um grafo bipartido com custos $c_{ij}$ nas arestas $[i, j] \in E$;\label{alb:let}\;
    encontre um limite inferior $c^*$ para o valor ótimo da função objetivo;\label{alb:bound}\;
    \AlgComment{por exemplo, $c^* := \max(\max_{i \in U} \min_{j \in V} c_{ij}, \ \max_{j \in V} \min_{i \in U} c_{ij})$}\;
    
    encontre um emparelhamento máximo $M$ no grafo $G[c^*]$, que tem a aresta $[i, j]$ \KwIff $c_{ij} \le c^*$;\label{alb:match}\;
    
    \eIf{$|M| = |U|$\label{alb:perfect}}{
        \KwStop \AlgComment{$M$ é um emparelhamento ótimo de custo $c^*$}
    }{
        \KwLet $L$ o conjunto dos vértices livres de $U$\label{alb:free}\;
    }

    % Continuation from the second image (The Main Loop)
    \While{$L$ não é vazio\label{alb:loop}}{
        escolha um vértice arbitrário $i \in L$;\label{alb:choose}\;
        $L := L \setminus \{i\}$;\;
        Dijkstra($i$); \AlgComment{o procedimento retorna um caminho $P$ que começa em $i$}\label{alb:dijkstra}\;
        
        \If{$P \neq \mathrm{nulo}$\label{alb:found}}{
            $M := M \ominus P$;\label{alb:aug}\;
            $c^* := \max(c^*, \ell(P))$\label{alb:cost}\;
        }
    }
    \AlgComment{$M$ é um emparelhamento máximo de custo mínimo $c^*$.}

    \caption{LBAP usando caminhos aumentantes \cite{burkard}}
    \label{alg:augmenting_lbap}
\end{algorithm}

Com referência às linhas do Algoritmo~\ref{alg:augmenting_lbap}:

\begin{itemize}
    \item \textbf{Ponto de partida (linhas~\ref{alb:let}--\ref{alb:free}):} Calcula-se um limite inferior $c^*$ para o ótimo (linha~\ref{alb:bound}), o mesmo do método dual: o maior entre os menores custos de cada linha e de cada coluna. Como arestas de custo até $c^*$ não pioram a solução, encontra-se de uma vez um emparelhamento máximo em $G[c^*]$ (linha~\ref{alb:match}), com qualquer algoritmo de cardinalidade máxima. Se ele já é perfeito (linha~\ref{alb:perfect}), o limite inferior foi atingido e a solução é ótima; senão, $L$ recebe os vértices de $U$ que ficaram livres (linha~\ref{alb:free}).
    \item \textbf{Laço de aumentos (linhas~\ref{alb:loop}--\ref{alb:dijkstra}):} Cada vértice livre $i \in L$ é retirado de $L$ uma única vez (linha~\ref{alb:choose}) e, a partir dele, o procedimento Dijkstra (Algoritmo~\ref{alg:dijkstra}) busca o caminho aumentante de menor gargalo, isto é, aquele cuja aresta mais cara é a mais barata possível (linha~\ref{alb:dijkstra}).
    \item \textbf{Atualização (linhas~\ref{alb:found}--\ref{alb:cost}):} Se existe caminho (linha~\ref{alb:found}), o emparelhamento é aumentado pela diferença simétrica com ele (linha~\ref{alb:aug}) e o valor da solução passa a ser o maior entre o valor atual e o gargalo $\ell(P)$ do caminho usado (linha~\ref{alb:cost}). Como cada caminho escolhido tem o menor gargalo possível, o valor final $c^*$ é o ótimo.
    \item \textbf{Complexidade:} O emparelhamento inicial custa no máximo $O(n^{2.5})$ com Hopcroft-Karp. O laço executa no máximo $n$ vezes, uma por vértice livre, e cada chamada do Dijkstra modificado custa $O(n^2)$ em uma matriz densa (ver a seguir), de modo que o total é $O(n^3)$.
\end{itemize}


% ALGORITHM 6.4: DIJKSTRA AND LABEL
\begin{algorithm}[H]
    \DontPrintSemicolon
    \SetAlgoLined

    \Fn{Dijkstra($i$)}{
        rotule todo vértice $j \in V$ com $(\alpha(j), \beta(j)) := (\infty, \mathrm{nulo})$;\label{dmod:init}\;
        $R := V$; \AlgComment{$R$ contém os vértices de $V$ ainda não examinados}\label{dmod:r}\;
        $\overline{\alpha}(i) := c^*, P := \mathrm{nulo}$;\label{dmod:root}\;
        Rotula($i$);\label{dmod:label0}\;
        
        \While{$R \neq \emptyset$\label{dmod:loop}}{
            encontre um vértice $j_1 \in R$ com $\alpha(j_1)$ mínimo;\label{dmod:min}\;
            \eIf{$\alpha(j_1) = \infty$\label{dmod:inf}}{
                $R := \emptyset$\;
            }{
                \eIf{$j_1$ está livre\label{dmod:free}}{
                    obtenha o caminho $P$ dado pela sequência $(i, \dots, \overline{\beta}(\beta(j_1)), \beta(j_1), j_1)$;\label{dmod:path}\;
                    $\ell(P) := \alpha(j_1)$;\label{dmod:len}\;
                    $R := \emptyset$\;
                }{
                    \KwLet $[i_1, j_1]$ a aresta do emparelhamento;\label{dmod:mate}\;
                    rotule $i_1$ com $(\overline{\alpha}(i_1), \overline{\beta}(i_1)) = (\alpha(j_1), j_1)$;\label{dmod:labeli}\;
                    $R := R \setminus \{j_1\}$;\;
                    Rotula($i_1$);\label{dmod:label1}\;
                }
            }
        }
    }
    
    \bigskip
    
    \Fn{Rotula($i$)}{
        \For{cada vizinho $j \in R$ de $i$\label{dmod:for}}{
            \If{$\alpha(j) > \max(\overline{\alpha}(i), c_{ij})$\label{dmod:relax}}{
                $\alpha(j) := \max(\overline{\alpha}(i), c_{ij})$;\;
                $\beta(j) := i$\label{dmod:pred}\;
            }
        }
    }

    \caption{Dijkstra modificado para caminhos aumentantes em LBAP \cite{burkard}}
    \label{alg:dijkstra}
\end{algorithm}

O procedimento mantém dois rótulos para cada vértice: para $j \in V$, $\alpha(j)$ é o menor gargalo conhecido de um caminho alternante de $i$ até $j$, e $\beta(j)$ é o vértice de $U$ que o precede nesse caminho; para $i' \in U$, $\overline{\alpha}(i')$ e $\overline{\beta}(i')$ têm o mesmo papel. Com referência às linhas do Algoritmo~\ref{alg:dijkstra}:

\begin{itemize}
    \item \textbf{Inicialização (linhas~\ref{dmod:init}--\ref{dmod:label0}):} Todos os vértices de $V$ começam com gargalo infinito e sem predecessor (linha~\ref{dmod:init}) e ficam no conjunto $R$ dos ainda não examinados (linha~\ref{dmod:r}). A raiz $i$ recebe o gargalo $c^*$ (linha~\ref{dmod:root}), e não $0$, porque arestas de custo até o valor atual da solução não a pioram; assim, entre caminhos de mesmo efeito sobre o resultado, qualquer um serve. Em seguida, os vizinhos de $i$ são rotulados (linha~\ref{dmod:label0}).
    \item \textbf{Escolha do próximo vértice (linhas~\ref{dmod:loop}--\ref{dmod:inf}):} Como no Dijkstra tradicional, escolhe-se o vértice de $R$ de menor rótulo (linha~\ref{dmod:min}). Se esse rótulo é infinito (linha~\ref{dmod:inf}), nenhum vértice restante é alcançável a partir de $i$, a busca termina e o caminho retornado é $P = \mathrm{nulo}$.
    \item \textbf{Coluna livre encontrada (linhas~\ref{dmod:free}--\ref{dmod:len}):} Se $j_1$ não está emparelhado (linha~\ref{dmod:free}), o caminho aumentante foi encontrado. Ele é reconstruído de trás para frente, seguindo os predecessores $\beta$ e $\overline{\beta}$ até $i$ (linha~\ref{dmod:path}), e seu gargalo é o rótulo de $j_1$ (linha~\ref{dmod:len}).
    \item \textbf{Extensão pela aresta emparelhada (linhas~\ref{dmod:mate}--\ref{dmod:label1}):} Se $j_1$ está emparelhado com $i_1$ (linha~\ref{dmod:mate}), o caminho alternante segue obrigatoriamente pela aresta $\{i_1, j_1\}$, que já pertence ao emparelhamento e não altera o gargalo. Por isso, $i_1$ herda o rótulo de $j_1$ e o tem como predecessor (linha~\ref{dmod:labeli}); $j_1$ sai de $R$ e os vizinhos de $i_1$ são rotulados (linha~\ref{dmod:label1}).
    \item \textbf{Procedimento Rotula (linhas~\ref{dmod:for}--\ref{dmod:pred}):} Para cada vizinho $j$ de $i$ ainda em $R$ (linha~\ref{dmod:for}), o gargalo de chegar a $j$ por $i$ é o maior entre o gargalo até $i$ e o custo $c_{ij}$. Se esse valor é menor que o rótulo atual de $j$ (linha~\ref{dmod:relax}), o rótulo é atualizado e $i$ passa a ser o predecessor de $j$ (linha~\ref{dmod:pred}). É o relaxamento do Dijkstra, com o máximo no lugar da soma.
    \item \textbf{Complexidade:} Cada vértice de $V$ sai de $R$ no máximo uma vez, e cada vértice de $U$ é rotulado no máximo uma vez. Com a matriz densa, a busca do mínimo (linha~\ref{dmod:min}) percorre $R$ em $O(n)$ e cada chamada de Rotula percorre os $O(n)$ vizinhos, o que dá $O(n^2)$ por chamada do procedimento.
\end{itemize}

\subsection{Heurísticas}
\label{sec:lbap_heuristicas}

Assim como na atribuição linear, os métodos gulosos para o problema de atribuição gargalo não têm garantia de aproximação e são, portanto, heurísticas (Seção~\ref{sec:tipos_metodo}). Esta seção apresenta duas heurísticas construtivas gulosas, ambas avaliadas no ambiente de testes: a simples, que serve de ponto de comparação, e a por arrependimento, que adapta o critério de escolha ao objetivo de minimizar o maior custo.

\subsubsection{Heurística gulosa simples}

A heurística gulosa simples percorre as $n^2$ posições da matriz de custos em ordem crescente e atribui a linha $i$ à coluna $j$ sempre que ambas ainda estão livres. Como a matriz é completa, o resultado é sempre uma atribuição perfeita. O defeito do método está no final do processo: as últimas linhas recebem as colunas que sobraram, cujos custos podem ser altos, e, como o objetivo é o \textit{maior} custo da atribuição, uma única escolha ruim no fim determina o valor da solução, criando um ``gargalo'' que as escolhas baratas do início não compensam.

\subsubsection{Heurística gulosa por arrependimento}

A heurística por arrependimento evita esse defeito decidindo primeiro as linhas que têm mais a perder. A cada passo, para cada linha livre $i$, sejam $c_i^{(1)}$ e $c_i^{(2)}$ o menor e o segundo menor custo de $i$ entre as colunas ainda livres. O \textbf{arrependimento} (\textit{regret}) da linha é
\begin{equation}
    r_i = c_i^{(2)} - c_i^{(1)},
    \label{eq:arrependimento}
\end{equation}
isto é, o quanto o custo de $i$ aumenta se a sua melhor coluna for ocupada por outra linha --- o \textit{custo de oportunidade} de não lhe dar essa coluna agora. Escolhe-se a linha de maior arrependimento e ela é atribuída à sua melhor coluna livre; se só resta uma coluna livre, o arrependimento é considerado infinito, pois a linha não tem alternativa. O critério é a adaptação, para o problema de gargalo, da heurística HGAP proposta por \citeonline{martello} para o problema de atribuição generalizada, que a cada passo atribui a tarefa com a maior diferença entre a sua melhor e a sua segunda melhor opção.

O Algoritmo~\ref{alg:lbap_gulosos} apresenta as duas heurísticas.

\begin{algorithm}[H]
    \DontPrintSemicolon
    \SetAlgoLined

    \caption{Heurísticas gulosas para o LBAP: simples e por arrependimento \cite{martello}}
    \label{alg:lbap_gulosos}

    \Fn{Guloso($C$)}{
        ordene as $n^2$ posições $(i, j)$ por $c_{ij}$ crescente\label{lg:sort}\;
        \For{cada posição $(i, j)$, nessa ordem\label{lg:for}}{
            \lIf{a linha $i$ e a coluna $j$ estão livres\label{lg:test}}{atribua $i$ a $j$}
        }
        \KwRet a atribuição $\varphi$ e seu gargalo $\max_i c_{i\varphi(i)}$\label{lg:ret}\;
    }

    \bigskip

    \Fn{Arrependimento($C$)}{
        \lFor{cada linha $i$\label{rg:sort}}{ordene as colunas por $c_{ij}$ crescente}
        $R := U$\label{rg:init}\;
        \While{$R \neq \emptyset$\label{rg:loop}}{
            \For{cada $i \in R$\label{rg:for}}{
                $j_1(i), j_2(i) :=$ primeira e segunda colunas livres na ordem da linha $i$\label{rg:best}\;
                $r_i := c_{i j_2(i)} - c_{i j_1(i)}$ \AlgComment{$r_i := \infty$ se $j_2(i)$ não existe}\label{rg:regret}\;
            }
            $i^* :=$ linha de $R$ com $r_i$ máximo \AlgComment{empate: menor $c_{i j_1(i)}$}\label{rg:choose}\;
            atribua $i^*$ a $j_1(i^*)$; $R := R \setminus \{i^*\}$\label{rg:assign}\;
        }
        \KwRet a atribuição $\varphi$ e seu gargalo $\max_i c_{i\varphi(i)}$\label{rg:ret}\;
    }
\end{algorithm}

O Algoritmo~\ref{alg:lbap_gulosos} é explicado a seguir, linha a linha:

\begin{itemize}
    \item \textbf{Guloso simples (linhas~\ref{lg:sort}--\ref{lg:ret}):} As posições são ordenadas por custo (linha~\ref{lg:sort}) e examinadas uma única vez, da mais barata para a mais cara (linha~\ref{lg:for}). Uma posição é aceita se sua linha e sua coluna estão livres (linha~\ref{lg:test}); uma posição rejeitada nunca é reconsiderada. O gargalo é o maior custo entre as posições aceitas (linha~\ref{lg:ret}).
    \item \textbf{Preparação do arrependimento (linhas~\ref{rg:sort}--\ref{rg:init}):} Cada linha guarda suas colunas em ordem crescente de custo, e o conjunto $R$ começa com todas as linhas.
    \item \textbf{Cálculo do arrependimento (linhas~\ref{rg:for}--\ref{rg:regret}):} Para cada linha livre, a melhor e a segunda melhor coluna livre são as duas primeiras colunas livres na sua ordem (linha~\ref{rg:best}), e o arrependimento é a diferença entre os seus custos, conforme a Equação~\eqref{eq:arrependimento} (linha~\ref{rg:regret}).
    \item \textbf{Escolha (linhas~\ref{rg:choose}--\ref{rg:assign}):} A linha de maior arrependimento é atribuída à sua melhor coluna livre e sai de $R$ (linha~\ref{rg:assign}). Os empates são desfeitos pelo menor custo e, depois, pelo menor índice de linha.
    \item \textbf{Complexidade:} No guloso simples, a ordenação das $n^2$ posições custa $O(n^2 \log n)$ e domina a passada, que é $O(n^2)$. No guloso por arrependimento, a ordenação das linhas também custa $O(n^2 \log n)$. Como uma coluna ocupada nunca volta a ficar livre, cada linha mantém um ponteiro para a sua primeira coluna livre, que só avança; o total de avanços é $O(n^2)$, e cada uma das $n$ iterações do laço examina $O(n)$ linhas. O custo total é, portanto, $O(n^2 \log n)$ para as duas heurísticas.
\end{itemize}

\textbf{Exemplo.} Considere a matriz de custos
\begin{equation}
    C = \begin{bmatrix} 3 & 8 & 6 \\ 7 & 2 & 9 \\ 5 & 1 & 4 \end{bmatrix},
\end{equation}
com linhas $1, 2, 3$ e colunas $1, 2, 3$. O guloso simples escolhe primeiro a posição mais barata, $(3, 2)$, de custo 1. A posição seguinte, $(2, 2)$, de custo 2, é rejeitada, pois a coluna 2 já está ocupada; aceita-se então $(1, 1)$, de custo 3. Restam apenas a linha 2 e a coluna 3, e a atribuição termina com $(2, 3)$, de custo 9, que é o gargalo da solução.

O guloso por arrependimento calcula, no primeiro passo, $r_1 = 6 - 3 = 3$, $r_2 = 7 - 2 = 5$ e $r_3 = 4 - 1 = 3$. A linha 2 é a que mais perde se não ficar com a coluna 2 e é atribuída a ela, com custo 2. No segundo passo, com as colunas 1 e 3 livres, $r_1 = 6 - 3 = 3$ e $r_3 = 5 - 4 = 1$, e a linha 1 recebe a coluna 1, com custo 3. Por fim, a linha 3 recebe a coluna 3, com custo 4. O gargalo é 4, que é ótimo: toda atribuição usa uma posição da coluna 3, cujo menor custo é 4, de modo que nenhuma atribuição tem gargalo menor.

O exemplo mostra por que o critério funciona: a linha 3 também preferia a coluna 2, mas tinha uma alternativa barata (a coluna 3, de custo 4), enquanto a linha 2 não tinha. Ainda assim, o critério olha apenas um passo à frente e não oferece garantia: há matrizes em que também ele termina com um gargalo alto, como mostram os resultados do Capítulo~\ref{cap:resultados}.
